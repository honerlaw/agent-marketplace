# Proposal: add-propose-ship-balanced

**Date**: 2026-06-29
**Status**: Shipped (2026-06-29)

## Goal
Add a fourth minerva lifecycle orchestrator skill, `minerva:propose-ship-balanced` — the middle rung between `propose-ship-quick` (the main model decides solo) and `propose-ship-auto` (a 3-agent `minerva:round-table` consensus panel at every gate). It runs the same end-to-end lifecycle (propose → work → review → promote → synthesize → ship → cleanup) on `propose-ship-quick`'s main-model-decides engine, but dispatches a **single fresh-context advisory reviewer** at exactly the decision gates where run-log telemetry shows independent review pays: scope check, approach selection, completion-verification (plus the rare never-elide divergence / replan-acceptance / replan-vs-FIX gates, only when they trigger). The main model decides first and arbitrates the reviewer's critique inline; there is **no 3-agent panel, no sequential Arbiter, and no consensus revision round**. The result is quick-class latency with auto-class assurance on the gates that matter.

The four orchestrators form a ladder by adjudication cost: `propose-ship` (human gates) · `propose-ship-quick` (main model decides solo) · `propose-ship-balanced` (one independent reviewer at the high-signal gates) · `propose-ship-auto` (3-agent consensus panels).

## Why
`propose-ship-auto` is thorough but slow, and unit 039 already harvested the cheap wins (panels → Sonnet, CONTEXT trimming). The remaining cost is **structural**: ~9 decision gates, each a Proponent+Skeptic dispatch in parallel *then a sequential Arbiter*, each possibly doubled by a revision round — up to ~6 subagent dispatches and 2 round-trips per gate. `propose-ship-quick` removes all of that (the main model decides every gate), but it also removes every independent check — the wrong trade once a change is bigger than a one-file tweak.

Run-log telemetry (a cross-tab of past auto runs' `## Panel decisions` scratchpad entries, gathered this session) shows the independence budget is mostly spent where it does not change outcomes:
- **completion-verification**: ~18 first-vote unanimous (3/3) vs ~2 that did real work — its value is independent *test reproduction*, not debate;
- **approach-selection**: ~13 revisions vs ~4 clean accepts — the one gate where independent review actually changes the outcome;
- **scope check**: mixed — rubber-stamps are common, but the misses (a wrong-sized unit) are expensive;
- **review triage**: ~10 `[skipped — small]`; **promote partition / TODO**: low-blast-radius churn.

So `balanced` spends exactly one reviewer where the data says it pays and decides everything else solo. A typical run drops from ~9 panels (up to ~50 subagent dispatches) to **3 single-agent checks, no Arbiters, no revision rounds** — because only scope, approach, and completion fire on every run; divergence/replan-acceptance/replan-vs-FIX add a reviewer only when that decision point is actually reached.

## Approach
Approach A v2, ratified 3/3 by the approach-selection panel after one revision round. Build a new self-contained skill `plugins/minerva/skills/propose-ship-balanced/`, mirroring `propose-ship-quick`'s structure with the decision mechanism swapped. It does **not** delegate to `minerva:round-table` (a single advisory reviewer is not a 3-agent consensus panel, so [[033]] does not bind it), and it does **not** modify any existing skill at runtime.

1. **`SKILL.md`** (≤9 KB, [[036]]) — phase map and hardcoded escalation triggers identical to `propose-ship-quick`; the protocol section becomes a **"Verify protocol"** section that points (with *read* directives) at the reference files. Frontmatter `name: propose-ship-balanced`, non-empty description.

2. **`references/verify-protocol.md`** — the differentiator. `propose-ship-quick`'s solo-decision protocol, plus:
   - **Fixed gate taxonomy.** A single reviewer fires at: scope check, approach selection, completion-verification (these three fire on **every run**); mid-work divergence, replan-acceptance, replan-vs-FIX (only **when that decision point is reached**, which is rare). All other gates — whole-proposal soundness, review triage, promote partition, TODO disposition — are decided **solo**, exactly like quick. This is a per-decision-*type* policy, not an up-front whole-run sizing classifier ([[014]]-compliant).
   - **Reviewer mechanism.** At a reviewer gate the main model decides first, then dispatches **one** fresh-context agent (`subagent_type: general-purpose`, `model: sonnet`) — a **Skeptic** at scope/approach/divergence/replan-acceptance/replan-vs-FIX, a **Verifier** at completion. Decide-first-then-review is intentional: a fresh-context reviewer carries no confirmation bias from the main model's reasoning, and reviewing the committed decision is cheaper than a parallel re-derivation. At most **one** dispatch per gate; **no** revision-round re-dispatch.
   - **Inline arbitration + the "load-bearing" threshold.** The main model is the Arbiter. It folds/escalates only for **load-bearing** critique, defined behaviorally: a critique is load-bearing iff it identifies (a) a violation of a documented `.minerva/knowledge/` constraint or a stated success criterion; (b) a missed dependency or integration risk the decision did not account for; (c) an overlooked scope surface/file; (d) [approach gates] a viable alternative strictly dominant on the stated criteria; (e) [completion gate] an unmet or only-partially-met criterion. *Not* load-bearing: stylistic disagreement, or re-weighting already-considered tradeoffs without new information. **Anti-circularity rule:** if folding would require a materially different decision **and** the main model cannot confidently tell whether the reviewer is right, that trips quick's escalation predicate (genuine ambiguity) → **escalate to the user**, never self-confirm.
   - **Verifier brief (completion gate).** Inputs: the success-criteria checklist (each criterion + the main model's claimed evidence + yes/no), `git diff <default>...HEAD`, and the proposal's `## Success criteria`. Task: for each criterion independently determine whether it is honestly met — do **not** trust the claimed evidence; reproduce it (read named files; where a criterion names a test/anchor, run a read-only command or grep to confirm the diff contains/passes it); actively try to **falsify** "done". Output: per-criterion `{met: yes/no/unsure + evidence-or-gap}`, then a verdict accept/revise/reject.
   - **Skeptic brief** — adapted from `round-table/references/briefs.md` and copied into this reference (self-contained convention, per [[042]]).
   - **Carried over from quick unchanged:** the escalation predicate, the scope-fit escape, the never-bypassed self-checks, the hardcoded escalation triggers, and the per-run escalation counter (halt-at-3).
   - **Logging.** One line per decision to `scratchpad.md` under a `## Balanced decisions YYYY-MM-DD` header, with prefixes `[decided]` (solo gate), `[reviewed — folded]` / `[reviewed — clean]` (reviewer gate; records what the reviewer flagged and whether it was folded), `[escalated to user]`, `[synthesis]`.

3. **`references/phases.md`** — mirrors quick/auto's phase map 1:1 (1 Propose, 2 Work, 2.5 Replan, 3 Review, 4 Promote, 4.5 Synthesis, 5 Ship gate, 6 Ship, 7 Cleanup). Per reviewer gate, an ARTIFACT + CONTEXT inclusion list for the dispatch, adapted from auto's (scope: seed + draft proposal; approach: candidate list + recommended pick + criteria; completion: checklist + diff + criteria; CONTEXT bounded to knowledge cited this session). Delegated phases (4.5 synthesize, 6 ship, 7 cleanup) carry the same auto-mode instructions as quick/auto.

4. **`references/governance.md`** — failure modes / escalation budget / observability / out-of-scope, parallel to quick's: global escalation counter halt-at-3, propose-phase abort, scope-fit escape, hard triggers, final-report-on-bail. Out-of-scope keeps "never modify an existing minerva skill at run time" and "no auto-cascade into new work units", and adds "never convene a 3-agent `minerva:round-table` panel — that is auto's mechanism."

5. **Delegations** — Phase 4.5 → `minerva:synthesize`, Phase 6 → `minerva:ship`, Phase 7 → `minerva:cleanup`, each led with the auto-mode instruction. Does **not** delegate to `minerva:round-table`.

6. **`evals/propose-ship-balanced/contract.json`** — frontmatter `{name: propose-ship-balanced, non_empty: description}`; body anchors `"Verify protocol"`, `"main model"`, the three delegations (`minerva:synthesize` / `minerva:ship` / `minerva:cleanup`), and `escalat`; reference anchors via the `file:` retarget — `"load-bearing"`, `"Verifier"`, `"Skeptic brief"`, `"Balanced decisions"`, `"escalation predicate"` (in `references/verify-protocol.md`), `"scope-fit escape"` and `"final report on bail"` (in `references/governance.md`), and a reviewer-dispatch anchor (in `references/phases.md`). `cross_surface {root_readme, plugin_readme, using_minerva_body}` all true.

7. **Catalog surfaces** (four, test-enforced) — root `README.md`, `plugins/minerva/README.md`, and `using-minerva/SKILL.md` body (the three covered by `cross_surface`), plus `pages/index.md` between the skills-catalog markers (covered separately by `tests/test_site_catalog.py`, per the [[042]]/[[010]]/[[034]]/[[038]] pattern — not a gap). `using-minerva` gets the four-rung routing line with concrete discriminators: medium-change examples (a multi-file refactor with a clear approach; a new feature with 2-3 plausible designs where a second opinion on the pick is wanted; a bug fix whose root cause spans a couple of modules) and anti-examples (a one-file tweak or trivial fix → `propose-ship-quick`, no reviewer cost; a change touching an unfamiliar public interface / cross-cutting contract, or one ambiguous/high-stakes enough to want agents arguing every gate → `propose-ship-auto`, full panels). Editing existing skills' catalog bodies is ordinary authoring, not the runtime self-modification the out-of-scope rule forbids.

## Open Questions
- **Name** — `propose-ship-balanced` (working name; conveys "the balanced middle of the ladder"). Alternatives considered: `-checked`, `-guarded`, `-verify`, `-review`. Confirmed unless the user prefers another.
- **Ladder-prose staleness in existing skills** — `propose-ship-quick` and `propose-ship-auto` each say "the three orchestrators form a ladder." Because this run *is* `propose-ship-auto`, whose out-of-scope rule forbids modifying existing minerva skills at runtime, this unit updates only the four established catalog surfaces and records a **followup** to refresh those "three"→"four" lines outside an auto run (a later quick/balanced run or a manual edit). The new skill's own docs describe the full four-rung ladder.
- **`behavioral.json` eval** — out of scope (behavioral evals are on-demand, not a CI gate; `contract.json` is the regression floor) — same call as 042.
