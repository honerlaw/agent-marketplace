# Proposal: synthesize-skill

**Date**: 2026-06-03
**Status**: Draft

> **Phase C** of the LLM-wiki effort — the synthesis layer. Phases 1 / B.1 / B.2 / B.3
> gave the corpus navigability (index + cross-refs), a deterministic detector, a
> read-only `minerva:lint`, and a gated `minerva:lint-fix`. Phase C adds the
> higher-order **thematic synthesis** layer Karpathy's LLM-wiki calls concept/overview
> pages — owned and regenerated by the LLM, gated, advisory.
>
> **Scope (panel-confirmed 3/3):** this unit ships the **capability** + the **first
> real `overview.md`** by dogfooding. Wiring `minerva:synthesize` into
> `minerva:propose-ship` / `minerva:propose-ship-auto` is **deferred to a follow-up
> unit**.

## Goal

Add a `minerva:synthesize` capability that:

1. reports the **un-synthesized scope** in `.minerva/knowledge/` via a *deterministic*
   signal (a `scripts/synthesis_status.py` the skill consumes), so the LLM can decide
   **IF** there is enough new scope to warrant (re)synthesis — exactly the user's
   requirement that the LLM decides whether to run at all;
2. when the LLM judges there is enough, **generates / refreshes** a theme-grouped
   `.minerva/knowledge/overview.md` (each theme = a short narrative + `[[NNN-type-slug]]`
   wikilinks), behind a user-confirmation gate;
3. as part of *this* unit, **dogfoods** the skill to produce and commit the **first real
   `overview.md`** synthesized through the corpus-max NNN at synthesis time.

## Why

The corpus has grown to 23 entries (001–023) with an `index.md` catalog and reciprocal
cross-refs ([[2026-06-03-decision-minerva-lint-read-only]] and the surrounding wiki phases) but
**no thematic synthesis layer**. Karpathy's LLM-wiki separates raw sources from
LLM-owned synthesis pages; minerva today has the sources + navigation but nothing that
reads *across* entries to surface themes. The user asked for the capability now, with
the LLM deciding **IF** to run based on whether enough un-synthesized scope exists — so
the deterministic "what's new since last synthesis" signal is the load-bearing piece.

## Approach

### `overview.md` lives as a SEPARATE file, never inside `index.md`

`overview.md` does **not** match the entry regex
(`ENTRY_RE = ^(\d{3})-([a-z]+)-.+\.md$`), so the **frozen** detector
(`scripts/knowledge_lint.py`) and the fixer (`scripts/knowledge_fix.py`) ignore it
entirely — the fixer rebuilds only `index.md` from its four `## Decisions/## Bugs/##
Patterns/## Constraints` sections, so a theme-grouped section *inside* `index.md` would
be silently clobbered (this is why the rejected `## Themes`-in-index approach was cut).
A separate file means **no frozen tool is unfrozen** and there is no overwrite hazard
([[2026-06-02-constraint-promote-narrowed-never-overwrite]] does not bind a brand-new owned
file).

`overview.md` carries a single state token, distinct from the index watermark:

```
<!-- synthesis-watermark: NNN -->
```

where `NNN` is the max entry NNN reflected by the synthesis. This is a **different
marker** from `index.md`'s `index-watermark` (the latter must always equal max NNN — an
integrity invariant; the synthesis watermark *deliberately lags*, and the lag is the
un-synthesized-scope signal). Its regex is single-sourced in the new script (it is a
new marker, so a new regex is legitimate, not a [[2026-06-02-constraint-knowledge-span-model-single-sourced]]
violation).

### `scripts/synthesis_status.py` — the deterministic signal

Importable `synthesis_status(knowledge_dir) -> dict` returning:

- `overview_exists`: bool;
- `synthesis_watermark`: int (`-1` when no `overview.md`, or when it carries no
  `synthesis-watermark` comment);
- `corpus_max_nnn`: int (`-1` when the corpus is empty);
- `unsynthesized`: sorted list of entry NNNs with `NNN > synthesis_watermark` — the
  un-synthesized **new scope**;
- `link_rot`: sorted list of `[[NNN-type-slug]]` stems appearing in `overview.md` that
  do **not** resolve to a live entry.

It **reuses** `knowledge_lint`'s `_strip_fences`, `ENTRY_RE`, and `WIKILINK_RE`
([[2026-06-02-constraint-knowledge-span-model-single-sourced]],
[[2026-06-03-constraint-skill-wraps-script-via-importable-api]]). Live entries are enumerated
via the `ENTRY_RE` glob over the knowledge dir — **not** `parse_index`, which only reads
`index.md`'s fixed Type-section catalog and would return an empty catalog (→ a *false*
clean) against a theme-grouped overview. The `overview.md` link scan is **fence-aware**
via `_strip_fences` so a fenced example link is never flagged
([[2026-06-03-constraint-wiki-edge-derivation-fence-aware]] explicitly names the Phase-C
synthesis tooling as a tool that must reuse `_strip_fences`). Missing `overview.md` →
`watermark = -1`, all entries un-synthesized, empty `link_rot`, **no crash** (mirrors
`parse_index`'s `exists: False` branch).

### `minerva:synthesize` skill — read-mostly, self-gating, gated write

A new skill (`plugins/minerva/skills/synthesize/SKILL.md`). Flow:

1. Bash-invoke `synthesis_status` via the importable API, anchored to
   `git rev-parse --show-toplevel` ([[2026-06-03-constraint-skill-wraps-script-via-importable-api]]).
2. Present the signal: the un-synthesized count / NNN list **and** any `link_rot`
   findings.
3. The LLM **decides IF** to (re)synthesize — weighing the new-scope count **and**, by
   judgment, whether in-place `## Related`/banner/body edits since the last synthesis
   materially change the picture (the watermark is a new-scope-only floor — see
   Limitations). If there is too little new scope, it reports that and stops.
4. If yes, it drafts the theme-grouped overview (narrative + fence-aware
   `[[NNN-type-slug]]` links per [[2026-06-03-constraint-wiki-edge-derivation-fence-aware]]),
   **gates on user confirmation**, writes `overview.md`, and bumps the
   `synthesis-watermark` to the corpus-max NNN at synthesis time.

It is **writer-shaped**: `allowed-tools` includes `Write`/`Edit`; it carries **no**
`read-only` anchor or read-only language (honest about mutating — the precedent is
`minerva:lint-fix`). The overview's *editorial quality* is LLM-judged and therefore
**advisory, never CI-gated** ([[2026-05-31-decision-behavioral-evals-provisional]]); only the
mechanical `link_rot` signal is deterministic. The skill body states this explicitly:
overview link-rot is mechanically gateable-in-principle (it is the same class as the
already-CI-gated entry `## Related` broken-link family), but is **deliberately kept
advisory** as a navigation-layer (not corpus-integrity) concern — 013's
mechanical-vs-judged exemption would *permit* gating; this is a deliberate choice, not a
013 prohibition.

### `overview.md` `## Limitations`

The committed overview documents the watermark's honest scope:

- it is a **new-scope-only floor** — it detects added entries (`NNN > watermark`), not
  in-place `## Related` / supersession-banner / body edits to already-synthesized
  entries (that drift is routed to the skill's IF-decision judgment);
- it attests synthesis **intent, not body content** — a watermark `>=` corpus-max with a
  stale body is *not* detectable by the signal;
- once *this* unit promotes its own knowledge entry (the next NNN, 024), the committed
  overview (watermark 023) will correctly show `unsynthesized: [024]` — the advisory
  detector working as intended.

### Catalog + contract + docs

- **Catalog ([[2026-05-21-constraint-minerva-skill-catalog-sync]]):** add `minerva:synthesize`
  to all three surfaces — the plugin README, the root README, and the `using-minerva`
  decision matrix. The matrix **Situation** text: *"After promoting several entries —
  when you want a theme-grouped overview of the knowledge corpus, or to check whether
  enough un-synthesized scope has accumulated to warrant (re)synthesis."* (a manually
  invoked maintenance skill while orchestrator wiring is deferred).
- **Contract ([[2026-05-31-constraint-skill-structural-contracts]]):** create
  `evals/synthesize/contract.json` (`skill: "synthesize"`; frontmatter `name:
  synthesize`, non-empty `description`, `contains: allowed-tools`; positive-substring
  anchors `synthesis_status`, `overview.md`, `git rev-parse --show-toplevel`,
  `synthesis-watermark`, `[[`, `advisory`, and a `gate`/`confirm` user-gate token;
  `cross_surface` all three). It carries **no** `read-only` anchor (writer-shaped, like
  `lint-fix`).

## Success criteria

- `scripts/synthesis_status.py` exposes importable `synthesis_status(knowledge_dir)`
  returning `{overview_exists, synthesis_watermark, corpus_max_nnn, unsynthesized,
  link_rot}`, reusing `knowledge_lint`'s `_strip_fences` / `ENTRY_RE` / `WIKILINK_RE`,
  enumerating entries via the `ENTRY_RE` glob (**not** `parse_index`), with the new
  `synthesis-watermark` regex single-sourced in the script.
- Missing `overview.md` → `synthesis_watermark = -1`, all entries un-synthesized, empty
  `link_rot`, no crash.
- `tests/test_synthesis_status.py` covers the **no-overview bootstrap** (REQUIRED) + a
  populated case (some un-synthesized) + a link-rot case (overview references a
  non-existent NNN, and a fenced example link is NOT flagged); it imports only
  `knowledge_lint` + `synthesis_status` (avoids the pre-existing `lib` collection
  abort); it is appended to `evals.yml`'s enumerated pytest list; green.
- `plugins/minerva/skills/synthesize/SKILL.md` is writer-shaped (`Write`/`Edit` in
  `allowed-tools`; **no** `read-only` anchor), Bash-invokes the importable API via the
  `git rev-parse --show-toplevel` anchor, presents the signal, has the LLM decide IF to
  synthesize, gates the write on user confirmation, bumps the watermark to corpus-max,
  and its body contains the word `advisory`.
- `evals/synthesize/contract.json` present with the positive-substring anchors above and
  `cross_surface` all three; `tests/test_skill_contracts.py` passes with `synthesize`
  enumerated.
- All three catalog surfaces + the `using-minerva` matrix list `minerva:synthesize`.
- `overview.md` carries the `## Limitations` note (new-scope-only floor +
  attests-intent-not-content + the staleness-by-1-after-promote note).
- **Deliverable:** the first real `.minerva/knowledge/overview.md` is committed
  (synthesized through corpus-max NNN at synthesis time); the live corpus stays
  detector-clean **and** fixer-clean (`overview.md` is invisible to both); and
  `synthesis_status` reports **zero `link_rot`** on the committed overview.

## Open Questions

- None load-bearing. Orchestrator wiring (`propose-ship` / `propose-ship-auto`) is
  explicitly deferred to a follow-up unit. The unit's own knowledge entry is
  `minerva:promote`'s job per the lifecycle and should cross-reference
  [[2026-06-03-constraint-wiki-edge-derivation-fence-aware]].

## Out of scope

- Wiring `minerva:synthesize` into `minerva:propose-ship` / `minerva:propose-ship-auto`
  (follow-up unit).
- CI-gating the overview's content or its `link_rot` (advisory only, per 013 — see the
  deliberate-asymmetry note).
- Editing the frozen detector (`scripts/knowledge_lint.py`), the fixer
  (`scripts/knowledge_fix.py`), or `index.md`'s structure.
- A `log.md` running changelog (a possible later Phase-C increment; not this unit).
